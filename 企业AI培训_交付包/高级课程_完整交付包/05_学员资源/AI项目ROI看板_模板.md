# AI 项目 ROI 看板模板（高级 · 学员用 · 通用企业版 V2.0）

> 用途：H4 算账的落地工具——沙盘里用它算回收期，回去后它就是每月要盯的那块板。
> 版本：V2.0 ｜ 2026-09-02 ｜ 对齐《高级大纲》H4（ROI 指标）+ 考核方式（规划方案 60%）
> 对标：GitHub 采纳指标体系（MAU/MEU + 用户分层 + 业务影响）+ 企业财务"预计与已验证分账"惯例。

**怎么用（3 步）**：
1. 沙盘 Day1 PM：选一个最痛的场景，把第一部分指标定死（基线必须已有数据来源，没有就先补 2 周采集）。
2. 沙盘 Day2：用第二部分算一个项目的五步账，写清回收期。
3. 回去后：每月 1 号填一次第三部分的月报，红黄绿标给高管看——**这块板每月亮一次，AI 项目才死不了**。

**两条铁律（写进肌肉记忆）**：
- 先建指标看板，再谈投入——顺序反了永远算不清。
- **预计 vs 已验证必须分两列**——混在一起的 ROI 汇报在董事会过不了。

### 1.2 采纳指标（项目推开了没有）

| 指标 | 基线 | 目标 | 采集方式 |
|---|---|---|---|
| MAU（月活用户） | | | |
| MEU（月活跃核心用户） | | | |
| 用户分层：铁粉 / 偶尔 / 尝鲜（占比） | | | 季度问卷 + 系统日志 |

**分层判据**（问卷三问定档）：每周用 ≥3 次 = 铁粉；每月用 = 偶尔；试过没用起来 = 尝鲜。
**警戒线**：铁粉占比 < 20% = 项目没立住，先修采纳再谈扩量。

## 第二部分：一个项目的 ROI 五步账（沙盘里算的那个）

| 步骤 | 内容 | 数字 | 预计/已验证 |
|---|---|---|---|
| ① 基线 | 现在这件事花多少人力/时间/差错 | | 已验证（必须） |
| ② 实验设计 | 小范围试多久、多少人、对照组怎么设 | | 计划 |
| ③ 价值量化 | 省了多少工时/差错的减少 × 单价 | | 预计 |
| ④ 危害/成本扣减 | 误报处理 + 培训 + 工具订阅 + 治理成本 | | 预计 |
| ⑤ 投资回收期 | (一次性投入 + 月度成本) ÷ 月度净收益 | | 预计 |

**净收益 = ③ − ④**。④ 漏项是高管最容易被打脸的地方——至少列：误报人工复核、培训工时、订阅费、治理/审计成本。

**回收期判据**：< 6 个月 = 直接批；6-12 个月 = 带组合逻辑批（讲清规模化后的摊薄）；> 12 个月 = 先砍范围重算，别硬推。

## 第四部分：高管汇报三句话（月报只念这三句）

1. 本月 AI 在 **__场景** 已验证省了 **__**（小时/差错/成本）。
2. 采纳面：**__** 人在用，铁粉占 **__%**（趋势：↑/→/↓）。
3. 风险/下月动作：**__**（哪个指标红了，停/改/推选了哪个，为什么）。

## 常见坑（讲师点评用，学员自查）

| 坑 | 症状 | 怎么救 |
|---|---|---|
| 指标贪多 | 定了 10 个指标，第二个月没人填 | 砍到 2-3 个业务指标 + 2 个采纳指标 |
| 预计当已验证 | 汇报里全是"预计能省" | 分两列，没跑完实验的只许写"预计" |
| 只算收益不算扣减 | ROI 算出来好得离谱 | 强制列 ④ 的 4 项最低成本 |
| 看板建完没人看 | 三个月没更新 | 固定每月 1 号 + 指定 owner + 进高管会议程 |
| 铁粉没分层 | "大家觉得挺好" | 问卷三问定档，看铁粉占比不看平均分 |
